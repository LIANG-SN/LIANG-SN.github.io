Mapping the AI Inference Stack: Where Six Infrastructure Companies Compete

An architectural and product-level comparison of Fireworks AI, Together AI, Modal, Baseten, fal and RadixArk—from kernels and runtimes to production platforms and model optimization.

Shengnan Liang · AI Infrastructure · 10 min read
The central idea

Same market, different entry points

An inference engine executes a model efficiently. An inference platform transforms that engine into a reliable, scalable service. A GPU cloud lets developers run arbitrary workloads; model APIs hide deployment details; media platforms specialize in video, image and audio. These categories overlap.

In a sentence: Fireworks focuses on optimized LLM serving and customization. Together spans model APIs, training and GPU compute. Modal sells programmable serverless AI infrastructure. Baseten emphasizes production model deployment. fal serves generative media. RadixArk builds around SGLang, Miles and managed inference.

The meaningful comparison is which complexity each product removes for its customers—and how deeply it can optimize that layer.

03 / Open source

If vLLM and SGLang exist, why hire inference engineers?

vLLM and SGLang already provide sophisticated batching, quantization, parallelism, KV caching and distributed-serving features. The gap between an open engine and a commercial offering is not simply “single GPU versus multiple GPUs.” Instead, teams must optimize a moving mix of workloads, models, hardware, traffic and reliability requirements.

01 · REQUESTS

Variable workloads

Short agent calls and 100k-token contexts need different packing, cache-aware routing and latency budgets.

02 · FLEETS

Production constraints

GPU placement, autoscaling, availability, noisy neighbors, cold starts and P99 latency drive costs.

03 · MODELS

Changing architectures

MoE, FP8/FP4, speculative decoding, draft models and quantized checkpoints continuously change the optimum.

The core engineering problem is finding the best model + runtime + hardware + routing combination while meeting quality and latency targets. Sometimes default configurations win. Sometimes custom kernels or workload-specific models are worth the expense.

The product is not “the ability to run a model.” It is predictable quality and latency at the lowest sustainable cost.
04 / Moats

Which advantages last?

  • Low defensibility: a thin OpenAI-compatible API wrapper around an existing runtime.
  • Medium defensibility: a specific kernel optimization or short-lived benchmark lead, which may be replicated or upstreamed.
  • Potentially stronger: workload-driven model–system co-optimization, robust operations, GPU capacity, customer trust and a feedback loop built on real traffic.

Even strong advantages are not guaranteed: open-source engines improve, hyperscalers integrate vertically and hardware economics shift. No throughput chart alone can identify the fastest provider without matching model quality, hardware, concurrency, context lengths and latency targets.

RadixArk’s tradeoff: investing in open SGLang benefits its own products and competing hosts. Its managed offering must add value beyond the shared engine.

05 / Engineering

Model–system co-design is a compelling intersection

Quantization-aware training, pruning, distillation and speculative draft-model training are most valuable when measured against actual serving behavior—not merely checkpoint size or standalone benchmark scores.

MODEL

Shape computation

QAT, pruning, distillation, draft models, attention and expert structures.

SYSTEM

Realize gains

Profile kernels, memory bandwidth, KV reuse, batching and prefill/decode.

MEASURE

Optimize the right metric

Task quality, TTFT, P50/P99 latency, utilization, throughput and cost per successful task.

This is a natural bridge from model compression to inference systems: prove that a model change improves end-to-end serving economics under a fixed quality and latency requirement.

从 GPU Kernel、Inference Engine 到商业推理平台，再到模型优化：对比 Fireworks、Together、Modal、Baseten、fal 与 RadixArk 的产品、技术和壁垒。

Shengnan Liang · AI 基础设施 · 约 10 分钟
核心观点

同一市场，不同切入点

Inference Engine 负责高效运行模型；Inference Platform 将它转变成可靠、可扩展的商业服务。GPU Cloud 让开发者运行任意工作负载，Model API 隐藏部署复杂性，多媒体平台专门服务图片、音频和视频。这些分类并不互斥。

一句话：Fireworks 重视 LLM 推理优化和定制；Together 覆盖模型 API、训练、GPU Compute；Modal 主打可编程 Serverless AI 基础设施；Baseten 强调生产级模型部署；fal 专注生成式媒体；RadixArk 围绕 SGLang、Miles 和托管推理构建业务。

真正值得比较的是各公司替客户解决了哪一层复杂性，及其在这一层的优化深度。

03 / 开源与商业化

有了 vLLM 和 SGLang，为什么还需要 Inference Engineer？

vLLM 和 SGLang 已经具备成熟的 Batching、Quantization、Parallelism、KV Cache，以及分布式 Serving。开源引擎与商业服务的区别不是简单的单卡与多卡。真正的难点是面对不断变化的业务流量、模型、硬件与可靠性约束，仍然交付最佳性能。

01 · REQUESTS

请求差异很大

短 Agent 调用和 100K Context 需要不同的 Batching、Cache Routing 和延迟预算。

02 · FLEETS

生产复杂性

GPU Placement、Autoscaling、容错、Cold Start、资源隔离、P99 延迟都会影响成本。

03 · MODELS

架构不断变化

MoE、FP8/FP4、Speculative Decoding、Draft Model、量化模型不断改变最佳运行策略。

核心工程问题是：在模型质量与延迟约束下，联合优化模型 + Runtime + 硬件 + Routing。有时默认开源配置就足够，有时必须投入定制 Kernel 或 Workload-specific 模型。

商业产品不只是「能运行模型」，而是在可持续的成本下稳定地交付模型质量和延迟。
04 / 技术壁垒

什么壁垒能够持续？

  • 低壁垒：给现成 Runtime 套一层兼容 OpenAI 的 API。
  • 中等壁垒：某个 Kernel 技巧或短期 Benchmark 领先，但可被复现或合入开源。
  • 潜在更强的壁垒：基于真实业务负载的模型-系统协同优化、可靠运维、GPU Capacity、客户信任和生产流量的反馈闭环。

即使是较强壁垒也不是永久的：开源框架不断进步，云厂商纵向整合，硬件经济性在变化。不同模型质量、并发、Context 和延迟目标下的吞吐量不能直接比较。

RadixArk 的矛盾：推动 SGLang 开源生态也让其他 Hosting 公司受益，因此它的托管服务必须提供额外价值。

05 / 技术方向

Model–System Co-design 值得关注

QAT、Pruning、Distillation 和 Speculative Draft Model Training 的价值，应通过真实 Serving 系统衡量，而不只是 Checkpoint Size 或离线 Benchmark。

MODEL

改变计算本身

QAT、剪枝、蒸馏、Draft Model、Attention 或 Expert 结构。

SYSTEM

实现实际加速

Kernel Profiling、显存带宽、KV Reuse、Batching 与 Prefill/Decode。

MEASURE

优化正确指标

任务准确率、TTFT、P50/P99、GPU 利用率、吞吐与每个成功任务的成本。

从 Model Compression 转向 Inference Systems 的自然路径就是：证明模型改变在固定质量与延迟要求下，真正改善端到端推理成本。
